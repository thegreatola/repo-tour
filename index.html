A codebase walkthrough, written by a model running in your browser.

Paste a public GitHub repo. A small language model downloads once, runs on your GPU, reads the repo file by file and explains it. There's no server and no API key. The only requests are to GitHub and, the first time, for the model.

What it's doing

    The walkthrough appears here as it's written.

    How it works

    Everything runs in this tab. The model is WebLLM running on WebGPU in a Web Worker, and the repo comes straight from GitHub's public API. Each model has a 4,096-token context window, so the agent never sees the whole repo. It works like a person skimming a codebase:

    1. Read the README. The file list is ranked: README and the package manifest first, then entry points like src/index.ts, with tests, lockfiles, vendored code and build output left out.
    2. Choose the next file. The model sees its notes so far and the 40 most promising unread files, and answers in JSON. Its answer is decoded against a schema whose only allowed paths are those 40, so it can't ask for a file that doesn't exist. It can only say it's done after reading two files.
    3. Take notes. Each file is cut to about 1,700 tokens and turned into a one-line role and up to four facts. Older notes shrink to one line so they all fit.
    4. Write the walkthrough from the notes alone, then check it: every file path it mentions is looked up in the repo. Paths it read are underlined, and paths that don't exist are struck through.

    Trade-offs

    Running in the browser means no server bill and nothing sent anywhere, and it means working within a small model. These are measured from the recorded runs on this page:

    What had to be cut

    • Whole files. With 4,096 tokens for everything, a file gets about 1,700. The top of a file stays (imports, exports, first definitions) and the rest is dropped, with a note saying how much.
    • Free-form tool calls. Small models don't call tools reliably, so the model never writes a tool call. It fills in a JSON form, and the browser does the fetching.
    • Breadth. Five files a run, at most. It's a first look at a repo, not a review of it.
    • Private repos. Only public repos can be read without a token, and asking for one would mean handling secrets on a static page.
